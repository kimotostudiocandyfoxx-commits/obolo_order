# MV キット マニュアル（止め絵でつくる版）

歌が1曲あれば、**油絵のような止め絵 × ゆっくりしたカメラ × 立体感 × 金の歌詞 × 光の演出**で、
壮大な正方形のミュージックビデオ（1080×1080 / MP4）をつくれます。

このマニュアルは、実際に1本の MV を「最初の設計 → 何十回もの手直し → 完成」まで作った全工程と、
その途中で依頼者から出た指摘（どこが安っぽい・どこが変・何が良かった）を、誰でもくり返せる手順にまとめたものです。

> **動画化（絵を動画生成で動かす）はこの手順に入っていません。**
> いちばん失敗が多く、お金もかかる工程なので、まず止め絵だけで MV を完成させます。
> 動画にするかどうかは、完成を見てから「ステップ12」で決めます。

---

## 0. できあがるもの・かかるもの

| | 目安 |
|---|---|
| 形 | 正方形 1080×1080、30fps、H.264 + AAC の MP4（2〜3分の曲で 60〜90MB） |
| 見た目 | 1場面＝1枚の絵。寄り・引き・左右のゆっくりしたカメラ。人物と背景が逆に動く立体感。金の明朝体の歌詞、光の粒、羽根、後光 |
| 絵の枚数 | 場面 15〜20枚 ＋ アップ 3〜5枚 ＋ 人物を消した背景（立体感を出す場面の数だけ） |
| 絵の費用 | 1枚 約14円（Seedream 5.0 Pro / Runware の場合）。描き直しを入れても 1本 300〜600円ほど |
| 時間 | 絵の生成 1回 3〜5分、全体の書き出し 1回 約30分（3並列）。手直しの往復が一番時間を使う |
| 必要なもの | Linux（または WSL）、Python 3.11+、Node 18+、ffmpeg、Playwright（Chromium）、画像生成サービスのキー |

## 1. 全体の流れ

| ステップ | やること | 道具 | 決めるのは |
|---|---|---|---|
| 1 | 素材を集める（曲・歌詞・写真・世界観） | — | 依頼者 |
| 2 | 曲を聴き分ける（歌声だけを取り出す・テンポと小節） | `separate.sh` `beats.py` | 自動 |
| 3 | 歌詞のタイミングを決める | `transcribe.py` `align_lyrics.py` `timing_sheet.py` | **耳で確定** |
| 4 | 絵コンテ（場面割り・カメラ・アップ・最後の旅） | `project.json` | 作り手 |
| 5 | 絵を描く（生成 → 見る → 描き直し） | 画像生成 | 作り手＋依頼者 |
| 6 | 立体感（人物を切り抜き、人物のいない背景を用意） | `seg.py` `sam.py` `make_layers.py` `plate_bg.py` | 自動＋目で確認 |
| 7 | 歌詞の見せ方（場面ごとの位置・縦横・大きさ） | `project.json` | 作り手 |
| 8 | 光と演出（光の粒・言葉の演出・最後の盛り上げ） | `project.json` | 作り手 |
| 9 | タイトルとエンディング | `project.json` | 依頼者 |
| 10 | チェックをくり返す | `qa.sh` | 作り手＋依頼者 |
| 11 | 書き出して渡す（速さ・色の仕上げ） | `make.sh` | 依頼者 |
| 12 | **完成後に**：動画化するか決める（任意） | `scripts/mv-art/video.mjs` | 依頼者 |

## 2. 準備

### 2-1. 道具を入れる（1回だけ）

```bash
bash mv-kit/tools/setup.sh            # 画像処理・音声認識・切り抜きの道具と、歌声分離/ビート用の Python 3.10 環境、モデル
npm i -g playwright && npx playwright install chromium   # 書き出し用（すでにあれば不要）
```

モデルは GitHub のリリースから取ります（Hugging Face は使いません）。置き場所は `~/.mvkit`。

### 2-2. プロジェクトをつくる

```bash
bash mv-kit/tools/new_project.sh ~/mv-projects/my-song /path/to/song.mp3
```

| フォルダ | 中身 |
|---|---|
| `project.json` | この曲のすべて（歌詞と時間、場面、タイトル、光…）。**作業の9割はこのファイルを書き換えること** |
| `song.mp3` | 曲 |
| `art/` | 場面の絵（`<名前>.jpg`、正方形）、人物を消した背景（`<名前>-plate.jpg`）、ジャケット `card.jpg`（任意） |
| `layers/` | 切り抜いた人物と背景（自動で作る） |
| `work/` | 歌声だけの音、音声認識の結果、ビート |
| `qa/` | チェック用の静止画と一覧 |
| `out/` | 書き出した MP4 |

### 2-3. プライバシーの約束（必ず守る）

- **プロジェクトフォルダは公開リポジトリに入れない。** 曲・歌詞・実在の人の写真や名前が入るため。キット（このフォルダ）だけを共有する。
- 実在の人を描くときは、**本人の許可を先にもらう**。
- 実在の人が出る MV は、公開ページ（誰でも見られる URL）に置かない。渡すときはファイルで渡す。
- 写真は生成サービスに渡すときだけ縮めて使い、保存場所（リポジトリなど）には残さない。

## 3. ステップ1　素材を集める

依頼者から受け取るもの：

1. **曲**（mp3）
2. **歌詞**（1行ずつ。画面で2段にしたいところは `／`）
3. **出てくる人の写真**（似せたい人。表情の違う写真が数枚あると、場面ごとに選べて強い）
4. **歌い手の絵**（歌い手を天使などのキャラクターにする場合）
5. **世界観**（今回は「天上の油絵・金の光・雲」）
6. **曲名・宛名・クレジット**（タイトルとエンドロールに使う）

写真は場面の表情で使い分けます（例：座っている写真→玉座、笑っている写真→祝福や二人の場面、腕を組んだ写真→巨大な姿）。
**笑顔の写真なのに似ない、ということもある**ので、似なかった写真は別の写真に替えて描き直します。

## 4. ステップ2　曲を聴き分ける

```bash
bash mv-kit/tools/separate.sh ~/mv-projects/my-song           # 歌声だけ → work/vocals.wav
~/.mvkit/py310/bin/python mv-kit/tools/beats.py ~/mv-projects/my-song   # テンポ・小節の頭 → work/beats.json
```

- 歌声だけの音は、歌詞のタイミング（ステップ3）と「歌声に合わせて光がふくらむ」演出（書き出し時に自動）に使います。
- 小節の頭（ダウンビート）は、**場面を切り替える瞬間**を合わせるのに使います（ステップ4の最後）。

## 5. ステップ3　歌詞のタイミング

### 5-1. 下書きを自動でつくる

```bash
python3 mv-kit/tools/transcribe.py   ~/mv-projects/my-song               # 歌声を文字にして、1文字ずつの時刻 → work/asr.json
python3 mv-kit/tools/align_lyrics.py ~/mv-projects/my-song lyrics.txt    # 歌詞の各行に「出る時刻 s」「歌い終わり e」を入れる
python3 mv-kit/tools/timing_sheet.py ~/mv-projects/my-song               # 確認用の図 → qa/timing.png
```

`align_lyrics.py` は句読点を MV の見せ方に整えます（行末の 、。 は消す・行の途中の 、 は全角幅のすき間）。

### 5-2. 耳で確定する（ここは省略しない）

歌声の聞き取りは、話し声よりずっと難しく、**行によってはまったく認識されません**（`match 0%  <- check by ear` と出る行）。
自動の結果は下書きとして扱い、全行を耳と図で確かめます。

- `qa/timing.png`：青い山＝歌声の大きさ、緑の線＝行の出る時刻、赤＝歌い終わり、青い短い線＝声が出始めた所、灰色＝小節の頭。
- **緑の線が、休みのあとに声が立ち上がる所にぴったり乗っているか**を見る。息つぎ・コーラス・前奏の声に乗っていたらずらす。
- 直すのは `project.json` の `lines[].s` と `lines[].e`（秒）。

ルール（依頼者の指摘から）：

- **1行目は、歌い出しと同時に出す。** 早く出ると一番目立つ失敗になる。
- **歌い終わったらすぐ消す**（キットは自動で「歌い終わり＋約1秒」で消し、次の行が続くときは自然につなぐ）。前の行が次の場面まで残ると気になる。
- 歌詞の句読点（、。）は画面に出さない。

## 6. ステップ4　絵コンテ

### 6-1. 場面の割り方

- **歌詞1〜2行に1場面**が基本。前奏はタイトルの場面、間奏は情景、最後はエンドロールの空。
- 歌詞の意味と絵を対応させる（例：失ったもの → 空っぽの箱、感謝 → ひざまずく天使、未来 → 歩き出す姿、結び → 神殿）。
- **主役の顔が出る場面**と**情景の場面**を交互にすると飽きない。
- サビには**アップ**を差し込む（顔の笑顔・目元、胸に当てた手、トロフィーなどの象徴物）。小節の頭で短く切り替えると効く。
- **最後は「旅」で終わる**：神殿などへカメラがぐっと近づき（`z: [1.0, 1.7]`）、そのまま次の絵（中の光景）へつながると、物語が締まる。

### 6-2. `scenes` の書き方

```json
{"t": 35.6, "img": "s03-person", "z": [1.26, 1.08], "c": [[0.5, 0.36], [0.5, 0.46]],
 "ray": [0.5, 0.08], "rs": 0.85, "faces": [[0.5, 0.2, 0.1]],
 "layers": {"a": [0.5, 0.7], "dir": -1, "pan": -1}}
```

| 項目 | 意味 | 目安 |
|---|---|---|
| `t` | 場面が始まる秒（前後 0.9秒ずつ重ねて溶け合う） | 小節の頭に合わせる（下） |
| `img` | 絵の名前（`art/<img>.jpg`） | |
| `z` | ズーム（始め→終わり）。1.0＝全体 | 寄る `[1.02, 1.16]` / 引く `[1.26, 1.06]` を交互に |
| `c` | 画面の中心（絵の中の位置 0〜1、始め→終わり） | 顔が上なら `0.36 → 0.46` などで顔を追う |
| `ray` | 光の筋が出る位置（絵の中の座標） | 太陽・後光の位置 |
| `rs` | 光の筋の強さ | 0.7〜1.1 |
| `faces` | 顔の位置と半径。**光の筋や粒を顔にかけない**ために必ず入れる | アップは半径 0.13〜0.16 |
| `layers` | 立体感を使う（ステップ6）。`a`＝人物の足元（全身）か首元（胸から上）、`dir`＝寄る(+1)/引く(-1)、`pan`＝左右 | |
| `tint` | 1 で夜っぽく少し青く | |

### 6-3. 場面の切り替えを小節に合わせる

```bash
~/.mvkit/py310/bin/python mv-kit/tools/beats.py ~/mv-projects/my-song --snap
```

各場面の `t` を、0.8秒以内の一番近い小節の頭へ動かします。**これだけで「きれい」から「気持ちいい」に変わります。**

## 7. ステップ5　絵を描く

### 7-1. 絵の型（全場面に付ける共通の一文）

```
Baroque Renaissance religious oil painting in the style of a grand ceiling fresco, warm golden divine light, god rays,
soft billowing cream clouds, pale blue sky, rich glazing, fine visible brushwork, cinematic square composition,
balanced centered framing that reads well in a 1:1 frame, ultra detailed, no text, no letters, no numbers, no watermark, no frame border.
```

- サイズは**正方形**（2048×2048 で描いて 1440 に縮める）。
- 1枚ごとの文は「何がどこにいて、何をしていて、光はどこから」を具体的に。

### 7-2. 実在の人に似せるコツ（いちばん大事）

- **文章で顔の特徴を説明しない。** 「目が細い・頬が…」と書くほどずれる。
- 参照写真を渡し、文はこれだけにする：
  `the man in the reference photo (keep his face and hairstyle exactly as in the photo), ...`
- 髪型の言葉に注意：「buzz cut（坊主）」と書くと**頭がつるつる**になった。髪型は写真に任せる。
- **場面に合う表情の写真を1枚**選んで渡す（何枚も混ぜない）。
- 似なかったら、写真を替えて描き直す。依頼者に「似ている版」を選んでもらい、その版を正にする。
- 体を変える（たくましくする・翼を付ける・上半身裸）のは文で書いてよい。顔だけは写真任せ。

### 7-3. 描いたら必ず見る（NG集）

| NG | 対処 |
|---|---|
| 似ていない／別の人種の顔になる | 写真を替える。文の顔の説明を消す |
| 小さな天使・子どもの絵が止められる（生成サービスの判定） | 白い布をまとわせる文を足す |
| 体の一部が不自然・見えてはいけない所が写る | 構図を指定し直す（「頭から胸まで」「腰は白い布で覆う」）。描き直し |
| 首から上が画面の外で、首が切れて見える | **頭まで入る構図**で描き直す（カメラで隠すより確実） |
| 額縁に人物が飾られている等、意味の通らない演出 | 外す。依頼者に意味の分からない飾りは要らない |

### 7-4. 人物を消した背景も描く（ステップ6で使う）

立体感を出す場面ごとに、同じ絵から人物だけを消した版を描きます（参照に元の絵を渡して編集）：

```
Edit this painting: remove <人物の説明> completely, so that only the empty background remains. Keep everything else exactly as it is —
the same sky, sun, light rays, clouds, architecture and colours, the same composition, the same oil-painting brushwork.
Fill the space where they were with the matching background so it looks naturally painted. No people, no wings, no halo, no text.
```

保存名は `art/<img>-plate.jpg`。

### 7-5. このリポジトリでの描き方（GitHub Actions）

- 順番表 `design/mv-art-queue.json` に `{ id, prompt, w, h, size, refs }` を足し、ワークフロー **MV art** を手動で実行すると、
  Seedream 5.0 Pro（Runware）で描いて `design/mv-art/out/` に保存します（`scripts/mv-art/paint.mjs`）。
- 参照写真はワークフローの入力（`ref1`〜`ref4`、縮めた JPEG の base64）で渡し、リポジトリには保存しません。
- 他の環境では、同じ文と参照写真で、使える画像生成サービスで描けば同じ手順です。

## 8. ステップ6　立体感（人物と背景を分けて、逆にゆっくり動かす）

```bash
python3 mv-kit/tools/seg.py         ~/mv-projects/my-song      # 人物の形を自動で取る（"layers" のある場面すべて）
python3 mv-kit/tools/sam.py         ~/mv-projects/my-song      # （必要な場面だけ）翼・後光など取りこぼしを点で指定して足す
python3 mv-kit/tools/make_layers.py ~/mv-projects/my-song      # 切り抜き人物 layers/<img>-fg.webp と、仮の背景 -bg.webp
python3 mv-kit/tools/plate_bg.py    ~/mv-projects/my-song      # art/<img>-plate.jpg があれば、背景を「描いた背景」に差し替え
```

- 動きは自動：**人物は 4〜6% 大きく**して切れ目を隠し、人物と背景を**反対向きにゆっくり**寄せ・引き・左右に流す。
- 仮の背景（自動で埋めたもの）は人物の形にぼやけが残る。**描いた背景（plate）に差し替えると見違える**。
- 翼・後光・細い物が切り抜きから漏れたら `layers/sam_prompts.json` に点を足す：
  `{ "<img>": [ [ [[u,v], …取りたい所], [[u,v], …取りたくない所] ] ] }`
- 細かい調整は `layers/layer_cfg.json`（`cut`＝消す楕円、`add`＝足す楕円、`ring`＝後光の輪）。
- 切り抜いた結果は必ず目で見る（人物が欠けていないか、背景に人物の影が残っていないか）。

## 9. ステップ7　歌詞の見せ方

### 9-1. 書き方

```json
{"s": 26.0, "e": 33.0, "text": "二行目の歌詞は／二段に分けられる",
 "place": [{"x": 0.065, "y": 0.835, "al": "l", "k": 0.93}, {"x": 0.935, "y": 0.925, "al": "r", "k": 0.93}]}
```

| 段の種類 | 書き方 | 意味 |
|---|---|---|
| 横書き | `{"x", "y", "al", "k", "sp"}` | `x` 基準位置・`y` 文字の下端・`al` 左/中/右寄せ（`l`/`c`/`r`）・`k` 大きさ（1＝54px）・`sp` 字間 |
| 縦書き | `{"v": 1, "x", "y", "k"}` | `x` 列の中心・`y` 列の上端。縦書きの複数列は**右の列から読む**ので、1段目を右に置く |

### 9-2. 配置のルール（依頼者の指摘から）

- **毎回同じ下の位置に出さない。** 場面ごとに絵が潰れない場所を選ぶ：空が広ければ上、人物が中央なら左右の縦書き、
  人物の左右に1列ずつ（呼びかけて応える形）、大事な四字熟語は大きく字間を空けて、など。
- **顔・手・主役の物に文字を重ねない。** カメラが寄ると絵が動くので、`qa.sh` で歌詞が出ている間の始めと終わりを両方見る。
- **漢字はひらがなより少しだけ大きい**（自動で 1.12倍）。
- 金の文字の**縁は髪の毛ほど細く**（太い縁は安っぽい）。文字は**じわっと・ふわっと**1文字ずつ現れる（自動）。
- 白い翼・明るい空の上でも読めるよう、文字の後ろにごく薄い影が**1文字ずつ**広がる（先に黒いもやが出ない）（自動）。
- 下に置く行があるときだけ、画面の下がほんのり暗くなる（自動）。
- 最後の一言（`"peak": true`）は大きく、`hold: [消え始め, 消え終わり]` で長く残す。

## 10. ステップ8　光と演出

### 10-1. 光の粒（`lights`）

`[種類, 秒, 横位置, 縦位置, 強さ, {幅}]`。**曲の盛り上がる所に、ゆっくり、毎回ちがう種類と場所で**。

| 種類 | 見え方 | 合う所 |
|---|---|---|
| `twinkle` | その場で星が目覚める（`{w, h}` の範囲） | 前奏・タイトル・余韻 |
| `shower` | 金の雨がゆっくり降る | 歌い出し・語りかけ |
| `bloom` | 中心からふわっと広がる＋柔らかな光のふくらみ | サビ前・大きな山 |
| `ring` | 光の輪が広がる | サビの頭・名前を呼ぶ所 |
| `spiral` | らせんを描いて昇る | 感情が高まる所 |
| `fountain` | 下から噴き上がる | 達成・誓い |

ルール（依頼者の指摘から）：

- **同じ場所・同じ種類・同じ速さをくり返さない。** 散らす。
- **ゆっくりの方が豪華**。速い弾けは安っぽい。
- **線や四角い枠が見えてはいけない**（キットの光の粒は端のない丸い光だけで描いているので出ない。自作で足すときも同じにする）。
- 急に画面全体が光る演出（フラッシュ）は使わない。

### 10-2. 自動で入るもの

- 漂う光のちり（2層）、舞う羽根（密度は `feathers: [[秒, 密度], …]` で曲の展開に合わせる）、光の筋。
- **歌声に合わせて**光の筋と後光がふくらむ（`work/vocals.wav` があれば）。
- 光の粒・羽根は**顔の上では消える**（`faces` を入れておくこと）。
- 最後の一言では、**散った光が集まって文字になり、最後は文字が光にほどけて空へ昇る**。`ascend` で光の昇る時間を合わせる。

### 10-3. 言葉の演出（`wordfx`）

大事な言葉だけに、文字と絵をつなぐ演出を付けます（入れすぎない）。

| 種類 | 見え方 | 例 |
|---|---|---|
| `tear` | その字から光のしずくが落ちる | 涙 |
| `halo` | その字のまわりに金の輪が開いて回る | 光・神 |
| `swell` | 一度大きく光ってから戻る | 永遠・奇跡 |
| `pour` | 絵の中の物（`targets` の絵と位置）から金の光があふれて流れ落ちる | 未来 → 杯 |

### 10-4. 曲の展開（`energy`）

`{"base": 0.22, "ramps": [[始め, 終わり, 増減], …]}`。静かな A メロ、サビで上げる、間奏で少し下げる、最後で上げて、終わりで下げる。光の強さに効きます。

## 11. ステップ9　タイトルとエンディング

```json
"title":  {"script": "À toi", "caps": "YOUR NAME", "small": "merci pour tout", "from": 3.2, "to": 18.0},
"ending": {"script": "Merci beaucoup", "caps": "POUR TOUT", "from": 150.0, "to": 157.4},
"credit": {"small": "Studio Name", "big": "名前", "from": 158.0, "to": 167.3}
```

- 英語・フランス語は**筆記体（Pinyon Script）＋字間を広く空けた細い大文字（Cormorant Garamond）**で、おしゃれに。
- タイトルは前奏の中だけ（1行目の歌詞の前に消える）。歌詞と同じ文言を重ねて出さない（依頼者の指摘）。
- 文字の縁は細く。依頼者が要らないと言った文字（スタジオ名など）は出さない。

## 14. ステップ12　完成後に決める：動画化するか（任意）

止め絵の MV が完成したら、依頼者と一緒に**動画化するかどうか**を決めます。ここから先は任意です。

### 14-1. 判断の目安

| 動画化に向く | 止め絵のままが良い |
|---|---|
| サビ・盛り上がり（翼がはためく、光があふれる、歩き出す） | 前半・語り（止め絵の立体感の方が品よく見えた） |
| 情景（ろうそく、雲、硬貨が落ちる） | 最後の一言・神殿（止め絵をゆっくり動かす方が荘厳） |
| | 小さな人物がたくさんいる絵（体が崩れやすい） |

今回の正式版は「前半＝止め絵の立体感、サビ以降＝動画、最後の一言＝止め絵」に落ち着きました。

### 14-2. 費用と失敗の実際

| モデル（Runware） | 結果 |
|---|---|
| Seedance 2.0 Fast（`bytedance:seedance@2.0-fast`） | **顔が別人に変わった**（1フレーム目から）。初期設定で音を付けるため、`settings.audio: false` がないと「著作権の恐れ」で拒否される |
| Seedance 1.0 Pro Fast（`bytedance:2@2`、`providerSettings.bytedance.cameraFixed: true`） | **顔がほぼ変わらない**。1本（5〜8秒）約 0.04ドル。こちらを使う |

よくある失敗：

- 首から上が画面外の絵を動かすと、**知らない顔が生えてくる** → その場面は止め絵のまま。
- 終わりの方で**翼が体の前に回る**など不自然 → 前半だけ使う（`vmax`）。
- **小さな天使の体が崩れる**（最初の空の場面）→ 止め絵に戻す。
- 動画は元の解像度が低め（960px）なので、止め絵より少し柔らかくなる。

### 14-3. 手順（このリポジトリの場合）

1. 順番表 `design/mv-video-queue.json` に `{ id, image, duration, cameraFixed: true, prompt }` を並べる。
   `image` は描いた絵、`prompt` は「何がどう動くか」だけ（例：`his great white wings breathe softly, petals float down. He keeps exactly the same face.`）。
   全体の共通文：`Slow, graceful, majestic motion in exactly the same oil-painting style. The camera stays fixed. Every face, body, pose and the composition stay exactly as in the first frame.`
2. 順番表を push するとワークフロー **MV video** が動き、`design/mv-art/video/<id>.mp4` に保存される（`scripts/mv-art/video.mjs`）。
3. **全部の動画を1コマずつ目で見る**（始め・中・終わり。顔・体・翼）。だめな動画は使わない。
4. プロジェクトの `vid/` に入れ、`project.json` に `video` を書く：

```json
"video": {"from": 77, "still": ["s06-temple"],
          "clips": {"s03-person": "v03-person"},
          "vmax":  {"v08-bow": 5.5},
          "vrate": {"v11-march": 0.55}}
```

| 項目 | 意味 |
|---|---|
| `from` | この秒より前の場面は止め絵のまま |
| `still` | 動画にしない場面 |
| `clips` | 絵の名前 → 動画の名前 |
| `vmax` | その動画は始めの何秒だけ使う（後半が変なとき） |
| `vrate` | その動画だけスロー（0.55 ≒ 半分の速さ） |

- 動画は元のコマのまま使い、コマとコマの間を柔らかく重ねるので、**カタつかない**（24fps→30fps の変換や速さ変更によるガタつきを防ぐ）。
- 動画にした場面では、止め絵の立体感（人物と背景の逆の動き）は使われない（絵そのものが動くため）。カメラのゆっくりした寄り・引きは残る。

## 付録B　今回の手直しから学んだこと（品質の基準）

1. 似せるのは写真に任せる。文で顔を説明しない。似た版を依頼者に選んでもらう。
2. 1行目は歌い出しと同時。歌い終わったらすぐ消す。句読点は出さない。
3. 歌詞は毎回ちがう位置・縦横・大きさで、絵を潰さない。漢字は少しだけ大きく。縁は極細。じわっと出す。
4. 光の演出はゆっくり、散らす、線や枠を出さない、フラッシュなし。
5. 意味の分からない飾り（額縁の中の人物、横切る小さな天使など）は外す。
6. 立体感は「人物を少し大きく」「背景は描き直したものを」「動きはゆっくり」。
7. 場面は小節の頭で切り替える。サビにアップ。最後はカメラが中へ入っていく。
8. 英語・フランス語の文字は筆記体＋細い大文字でおしゃれに。不要な文字は出さない。
9. 書き出しは等速と速い版を見比べて選んでもらう（今回は1.2倍）。
10. 動画化は最後に決める。顔が変わらないモデルを使い、全コマを見て、だめな所は止め絵に戻す。

## 付録C　困ったとき

| 症状 | 原因と直し方 |
|---|---|
| ある場面が真っ黒 | `art/<img>.jpg` がない（build.py が WARNING を出す） |
| 歌詞がずれる | `lines[].s` を `qa/timing.png` と耳で直す。速さを変えても秒は元の曲のまま |
| 歌詞が顔に重なる | その行の `place` を動かす（縦書きにする・反対側へ・上へ） |
| 人物のまわりがぼやける | 人物を消した背景を描いて `art/<img>-plate.jpg` に置き、`plate_bg.py` |
| 翼や後光が切れる | `layers/sam_prompts.json` に点を足して `sam.py` → `make_layers.py` |
| 書き出しが途中で止まる | `make.sh` の出力の `pageerror` を見る（`project.json` の書き間違いが多い） |
| 動画の場面がカタつく | キットの最新の `src.html` を使う（元のコマ＋重ね描き）。スローは `vrate` |
