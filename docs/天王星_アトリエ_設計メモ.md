# 天王星「天空のアトリエ」と おぼろ商店 ― 受注生産グッズの設計メモ

作成日：2026-10-13
対象：OBOLO 開発・運営チーム（社内用。弁護士・税理士・工場への相談前の叩き台）

> **調べ方について**
> この調査では、各社の公式サイトを直接開けなかった（ネットワークの方針で接続を拒否された）。ここに書いた事実はすべて、検索結果に出た公式ページの抜粋をもとにしている。事実確認で「wrong（誤り）」になった主張は直したうえで使い、「unverified（未確認）」の主張には **【要確認】** を付けた。数字と条件は、契約の前に必ず各社へ直接確かめること。

## 0 前提（決まっていること）

- 天王星＝**天空のアトリエ**。空に浮かぶアトリエに、会員が気に入ったもの（自作アニメのキャラで作ったグッズなど）を飾る。キモリンもブラックタイガードラゴンのグッズを飾っている。
- アトリエの真ん中に **おぼろ商店** がある。会員が「出したい」と申請したグッズは、権利と安全の確認だけで並ぶ。出来の良し悪しでは落とさない。
- **売り手は会社（OBOLO）**。会員は作品の取り分を受け取る（SUZURI／LINEスタンプと同じ形）。
- 支払いは**現金だけ**（カードなど、Stripe を想定）。**マナは画像を作るときだけ**に使い、売り買いには使わない。
- **在庫を持たない受注生産**。OBOLO がグッズのテンプレを用意し、工場の商品と自動でつなぐ。注文が入ったら工場が作り、お客さんに直接送る（OBOLO 名義で、余計な同梱物なし）。
- まずは日本国内の販売と配送。海外は将来。
- 技術：Next.js＋NestJS＋PostgreSQL。自前で作る（Shopify は使わない）。
- 物語との一致：売れた数・★・ランキングは人に見せない。画面に「AI」という言葉を出さない。

## 1 結論

**おすすめの組み方：主工場は1社（イメージ・マジック）。アパレルの予備と技術検証に2社目（Printio）。海外は第3段階で Gelato を足す。**

| 役割 | 工場 | 理由 |
|---|---|---|
| **主工場（1社目）** | **イメージ・マジック**（オリジナルプリント.jp の運営元。生産管理API または maker town DTAPI） | 条件が一番そろっている。①自社のシステムから API で加工・出荷を指示できる（生産管理API。パートナー側で決済が済んだあとに指示する形）②**パートナー名義で加工・出荷**できる③国内の大手工場で、アクスタ・Tシャツ・トート・マグなど**推し活グッズの品目が広い**④講談社「ヤンチャグッズ」が DTAPI を採用した実績がある（2026年9月2日発表、発注から2か月で提供＝同社の発表）。 |
| **2社目（品目で使い分け）** | **Printio**（株式会社OpenFactory） | **API の仕様書が公開されている**（2025年10月21日）。retailer ID とトークンをもらえばすぐ試せるので、イメージ・マジックとの交渉中に「注文→工場→追跡番号」の流れを先に作って検証できる。Tシャツ・トートなど25種類以上（17LIVE の事例）。製造ステータスと追跡番号を API で受け取れる（2022年の発表資料）。2026年4月の資金調達で、対応品目を増やす方針。 |
| 将来（海外） | **Gelato** | 日本でも現地生産していて（公式の日本ページ）、32か国の工場網を1つの API で使える。白ラベルで、領収書・請求書を箱に入れない。 |

**選んだ考え方**

1. OBOLO の客層（15〜20歳・アニメ・推し活）で一番売れそうなのは **アクリルスタンド・缶バッジ・ステッカー**。この品目を「API＋OBOLO名義の直送＋国内生産＋1個から」で扱える候補は、調べた範囲では**イメージ・マジックしかない**。
2. ただし、イメージ・マジックは**条件が問い合わせ制**で、導入に**1〜2か月**かかる（公式の目安）。API の仕様・料金は公開されていない。だから、待っている間に **Printio で仕組みを先に作る**。
3. NestJS の中に **「工場アダプタ」** の層を作り、テンプレごとに「どの工場に送るか」を設定で切り替えられるようにする。工場が増えても、変わっても、画面と注文の流れは変えずに済む。
4. 工場は**最大2社**に絞る。届くまでの日数・品質・問い合わせの窓口がばらばらになるのを防ぐため。

**イメージ・マジックとの話がまとまらなかったときの代わり**

- アパレル：Printio を主工場にする。
- アクスタ・缶バッジ：**pixivFACTORY**（品目は80種類以上で推し活向け。法人向けの窓口あり。ただし外部向けの発注 API は見つからない）か **UP-T**（缶バッジ1個から、通常3営業日で発送。公開 API は見つからない）に**業務提携として相談**する。API がない場合は、OBOLO の管理画面から1日1〜2回まとめて発注する半自動の形で始める。

**選ばなかった工場**

- **SUZURI**：API で商品は作れるが、注文の API が見つからない。売り手と発送元が SUZURI になるので、「売り手は OBOLO」の形と合わない（取り分の仕組みのお手本としては参考にする）。
- **Printful**：日本の提携施設（熊本・石川など）で作れるのは主にアパレル。しかも**提携施設で作る注文にはロゴ入りの納品書が付かない**（公式ヘルプ）。日本の情報は約5年以上前のもの。なお Printful と Printify は2024年11月5日に合併を発表している（ブランドは当面別々）。
- **Printify・Gooten・Prodigi**：日本の工場が確認できない（Gooten は工場の地域に日本がない）。海外から送ると日数が長く、関税・消費税もかかりうる（下の注意を参照）。

> **海外から日本に送ることの注意**：今は課税価格1万円以下なら関税・消費税が免除されるが、ニット製の衣類（Tシャツなど）は対象外で、少額でも課税されうる（税関）。さらに**2026年3月31日に成立・公布された改正法**（令和8年法律第12号）で、通信販売で輸入する1万円以下の貨物にも消費税がかかるようになる。施行は2028年4月1日と民間の解説にある **【要確認：財務省の原文】**。日本国内で作る意味はさらに大きくなる。

## 4 注文から到着までの流れ

### 4.1 全体の流れ

| # | 段階 | 誰が | 何をする | システムの動き |
|---|---|---|---|---|
| 1 | **申請** | 作者（会員） | アトリエに飾っているグッズの絵から「おぼろ商店に出したい」を押す。テンプレを選び、チェック項目に答える（8章） | `listing_applications` を作る。15〜17歳は**保護者の同意**がなければ申請を受け付けない（7章） |
| 2 | **確認** | 自動チェック → 運営の人 | 権利と安全だけを見る。出来では落とさない | 自動チェックの結果を付けて、確認待ちの列に入れる。目安は2営業日以内。通らなければ「ここを直せば出せます」を返す |
| 3 | **おぼろ商店に並ぶ** | システム | 商品ページを作る | `products` を公開。工場の商品コードとつなぐ（工場によっては事前に商品を登録する。Printio は商品登録の API がある）。**売れた数・★・ランキングは表示しない** |
| 4 | **注文** | お客さん | カート → 最終確認画面（特商法12条の6の表示）→ 注文確定 | お届け目安を計算して画面に出す（5章） |
| 5 | **決済** | お客さん／Stripe | カードで支払い。**3Dセキュア（EMV 3-Dセキュア）を必ず使う** | **注文確定の時に売上を確定する（前払い）**。理由は下の 4.2 |
| 6 | **注文確認メール** | システム | 特商法13条の項目を入れて、承諾を知らせる（5章の文例） | 決済の成功を Stripe の Webhook で受けてから送る |
| 7 | **工場へ自動発注** | システム | 工場アダプタから工場の API へ発注 | 決済が済んだ注文を**数分ごとにまとめて**送る。同じ注文を二重に送らないよう、注文番号を工場側の重複防止のキーにする。失敗したら時間をあけて再送し、3回だめなら**運営の画面に赤で出す** |
| 8 | **製作** | 工場 | 作る | 工場から製造ステータスを受け取る（Webhook か定期的な問い合わせ）。「製作中」を注文画面に出す |
| 9 | **発送** | 工場 | OBOLO 名義で直送 | 追跡番号を受け取る → 発送メール（追跡のリンク）とアプリ内の通知 |
| 10 | **追跡** | お客さん | 注文画面で状況を見る | 運送会社の状況を定期的に確かめる。お届け目安の最終日を過ぎそうなら遅延の連絡（5章） |
| 11 | **到着** | お客さん | 受け取る | 配達完了を記録。届いて**7日間**は不良品の受付期間 |
| 12 | **作者に「売れたよ」と取り分** | システム → 作者 | 注文が入った時点で、作者だけに「売れたよ」と知らせる。取り分は**受付期間が過ぎてから確定** | `royalty_ledger` に「見込み」→「確定」と記録。毎月締めて、翌月末に払う（7章） |

### 4.2 決済のタイミング：注文時に売上確定（前払い型）にする

- Stripe のカードのオーソリ（与信だけ取って、あとで売上を確定する方法）は**通常7日間**で切れる。Visa の加盟店側から始める取引は実際には4日18時間ほど。
- 最長30日の延長オーソリは、**日本の事業者の取引には使えない**（Stripe 公式）。
- 受注生産は届くまで7日を超えることが多いので、「発送したら売上確定」は使えない。
- そこで、**注文確定と同時に売上を確定**する（SUZURI など多くの受注生産サービスと同じ）。工場が作れなかった・不良で作り直せないときは**全額返金**する。
- 注意：Stripe で返金しても、**元の決済手数料は戻らない**（公式）。この分は OBOLO が負担する前提で原価を見積もる。
- 前払いなので、特商法13条の通知（注文確認メール）が必要になる。「遅滞なく送れば通知は要らない」という例外はあるが、その目安（約1週間など）は解釈が分かれる【要確認】。**受注生産では必ず通知を出す**設計にする。

### 4.3 注文の状態（状態遷移）

```
決済待ち → 支払い済み → 工場へ送信中 → 工場が受付 → 製作中 → 発送済み → 配達完了 → 受付期間終了（取り分確定）
                 ↘ 工場エラー（再送／運営が対応） → 作り直し or 返金
発送済み → 遅延（目安超過） → 待つ or キャンセル・返金
発送済み → 返送（住所不明など） → 再送 or 返金
```

### 4.4 工場アダプタ（NestJS）

```ts
interface FactoryAdapter {
  createOrder(order: FulfillmentRequest): Promise<{ factoryOrderId: string }>;
  getStatus(factoryOrderId: string): Promise<FactoryStatus>;      // 製作中・発送済み・エラー
  cancelOrder(factoryOrderId: string): Promise<void>;
  parseWebhook(req: unknown): FactoryEvent;                       // 製造ステータス・追跡番号
  normalizeAddress(addr: JpAddress): unknown;                     // 工場ごとの住所の書き方に変換
}
```

- 住所の書き方は工場ごとに違う（Gelato は日本語で入力、Printful は英字を求めることがある）。変換はアダプタの中で行う。
- 工場に渡すのは**氏名・住所・電話番号・商品情報だけ**。メールアドレスは渡さない。

## 5 届くまでの目安の見せ方

### 5.1 計算のしかた

```
お届け目安（最短） = 注文日 + 製作の営業日数(min) + 配送日数(min)
お届け目安（最長） = 注文日 + 製作の営業日数(max) + 余裕（2〜3営業日） + 繁忙期の上乗せ + 配送日数(max)
発送期限          = 注文日 + 製作の営業日数(max) + 余裕 + 繁忙期の上乗せ
```

- 営業日は**日本の祝日カレンダーと工場の休み**で数える。土日祝は数えない。
- カートに複数の商品があるときは、**一番遅い商品**に合わせる。
- 最初は工場の公式の数字に余裕を足して、**全体で10〜20日ほど**から始める（受注生産の日数は1〜3週間ほどという調査の結果より）。実際に届いた日を記録し、**9割以上の注文が目安の範囲に入る**ように少しずつ縮める。
- 同じ計算を、商品ページ・カート・最終確認画面・注文確認メールの**すべてで使う**（場所によって日付がずれないように）。

### 5.2 文言の例

**商品ページ（価格の下）**
> ご注文を受けてから、ひとつずつ作ってお届けします。
> **お届け目安：10月27日（火）〜11月2日（月）ごろ**（今ご注文の場合）
> 作るのに少し時間がかかります。プレゼントなどで日にちが決まっているときは、余裕をもってご注文ください。

**カート**
> このカートのお届け目安：**10月27日（火）〜11月2日（月）ごろ**
> いちばん時間がかかる商品（アクリルスタンド）に合わせて、まとめてお届けします。

**最終確認画面（特商法12条の6で必要な項目をまとめて表示）**
> - 商品と数量：アクリルスタンド（S）×1
> - お支払い金額：商品 ○○円＋送料 ○○円＝合計 ○○円（税込）
> - お支払いの方法と時期：クレジットカード／ご注文の確定と同時にお支払い
> - **発送の期限：10月30日（金）までに発送します**（お届けは11月2日ごろまで）
> - 返品について：ご注文を受けてから作るため、お客さまのご都合による返品・交換はできません。不良品・注文と違う商品が届いたときは、届いてから7日以内にご連絡ください（6章）
> - ご注文の取り消し：注文を確定したあとは、工場が作り始める前の場合に限り取り消せます【要確認：取り消しを受ける時間の範囲】

**注文確認メール（特商法13条の通知を兼ねる）**
> 件名：【おぼろ商店】ご注文を承りました（注文番号 OB-123456）
> ご注文を**お受けしました**。
> - 販売者：株式会社○○（OBOLO）／住所：○○／電話：○○
> - お受けした金額：○○円（10月13日にお支払いを確認しました）
> - 商品と数量：アクリルスタンド（S）×1
> - **発送の期限：10月30日（金）まで**（お届け目安：10月27日〜11月2日ごろ）
> 作り始めたら、アプリとメールでお知らせします。

**通知（アプリ内・メール）**
- 製作開始：「アトリエの工房で、あなたのグッズを作り始めました。」
- 発送：「おぼろ商店からグッズを送りました！ 追跡はこちら → （リンク）」
- 到着予定日：「明日ごろ届く予定です。」
- 到着後：「グッズは無事に届きましたか？ 気になるところがあれば、7日以内に教えてください。」

### 5.3 遅れたとき

- 発送期限の**1営業日前になっても発送の記録がない注文**は、自動で遅延の連絡を出す（運営にも知らせる）。
- 文言の例：
  > ごめんなさい。ご注文のグッズ（注文番号 OB-123456）の発送が遅れています。
  > **新しい発送の目安：11月5日（木）まで**
  > このまま待つか、ご注文を取り消して全額返金を受けるかを選べます。 [待つ] [取り消して返金]
- 2回目の遅れが出たら、運営の人が直接連絡する。
- 「急いでほしい」という個別の依頼には応じない（UP-T・SUZURI と同じ）。早く届ける有料の特急は、第1段階では作らない。

## 6 返品・不良品・届かないとき

**基本の考え方**

- 通信販売にクーリング・オフはない。
- 返品の決まり（返品特約）を書かないと、届いてから8日間は申込みを解除できる（特商法15条の3。条文番号は e-Gov で【要確認】）。だから、返品特約を**商品ページ・カート・最終確認画面・特商法の表記ページ**のすべてに、見やすく書く。
- 民法の契約不適合責任など、特約では外せない責任があるかは**弁護士に確認**【要確認】。

| 場合 | 対応 | 費用 | 画面・表示 |
|---|---|---|---|
| お客さまのご都合（イメージと違う、サイズ違いなど） | 受けない | — | 「ご注文を受けてから作るため、お客さまのご都合による返品・交換はできません」 |
| **不良品**（印刷のかすれ・欠け、割れ、汚れ） | 届いて**7日以内**に、注文画面から**写真付き**で連絡 → 確認 → **作り直し**（作れなければ返金） | 工場との契約で**工場が負担**（作り直し）にする | テンプレごとに「不良とみなす基準」（色の差・印刷のずれの許す範囲）を公開する |
| **注文と違う商品** | 注文番号・氏名・商品名・違いが分かる写真を送ってもらう → 正しい商品を送る | 工場負担 | 同上 |
| **届かない**（追跡で止まっている、配達済みなのに見つからない） | 追跡を確認 → 運送会社に調査を依頼 → 見つからなければ作り直して送る or 返金 | 契約で決める（運送事故は工場・運送会社） | 「追跡の状況が○日変わらないときは、こちらから調べます」 |
| **住所の間違いなどで戻ってきた** | 本人に連絡して住所を直してもらい再送（送料の扱いは決める）or 返金（送料を引くかは【要確認】） | お客さま負担を基本にする案【要確認】 | 最終確認画面で住所をもう一度見てもらう |
| 工場が作れない（欠品・廃番など） | 全額返金。作者にも知らせる | OBOLO 負担（決済手数料は戻らない） | 「材料が手に入らず、作れなくなりました。全額お返しします」 |

- 事前の連絡なしに送り返されたものは受けない（SUZURI と同じ）。
- 返金・作り直しになった注文の**作者の取り分は確定させない**（7章）。

## 7 作者の取り分の払い方

### 7.1 地球の銀行の画面

- 取り分は **地球の銀行** の画面で見る。表示は**本人だけ**。他の人のアトリエやおぼろ商店には、**売れた数・金額・★・ランキングを一切出さない**。
- 画面の例：
  > 地球の銀行
  > **今月の取り分（見込み）：1,200円**
  > 確定した取り分：800円（11月30日にお振り込み予定）
  > 「天空のドラゴン アクスタ」が売れました（10月13日）
- 「見込み」と「確定」を分けて見せる。
- 現金の取り分は**マナとは別の帳簿**にする（マナは売買に使わないので、取り分をマナに替えることもしない）。

### 7.2 確定と振込のルール（案）

- 取り分は **配達完了＋7日の受付期間が過ぎたら確定**。返金・作り直しになった注文は確定しない。
- **毎月末に締めて、翌月末に振り込む**（SUZURI は申請月の翌月末）。
- **最低振込額**を決める（例：1,000円）。届かない分は翌月に持ち越す。
- 振込手数料の負担（SUZURI は3万円未満176円を本人負担）を決める。

### 7.3 未成年の作者（15〜17歳）

- 2022年4月から成年は18歳。未成年が親の同意なしに結んだ契約は、原則として取り消せる。LINE Creators Market も、未成年は法定代理人の同意を求めている。
- そこで、**おぼろ商店への申請**と**振込先の登録**のときに、**保護者の同意を必須**にする（保護者本人の確認と、同意の記録を残す）。
- 15歳未満の会員は、家族と一緒に使う前提。販売の申請と取り分は保護者のアカウントで扱う案【要確認】。
- 振込先を**本人名義の口座**にするか**保護者名義の口座**にするかは、税（誰の所得か）と規約の両方に関わる → **税理士・弁護士に確認**。

### 7.4 税の手続き（作る前に税理士と決める）

- 個人に払うデザインの報酬・著作権の使用料は源泉徴収の対象（1回100万円以下は10.21%）。ただし、**グッズの取り分がこれに当たるか**は契約の形で変わる可能性があり、**不明** → 税理士に確認。
- 同じ人への1年の支払いが**5万円を超えたら支払調書**を出す（消費税が分けて書いてあれば税抜きで判断してよい）。そのため**マイナンバーを集める仕組み**が必要になる可能性がある。
- 多くの作者は免税事業者。インボイスの経過措置は、2026年10月〜2028年9月が70%、2028年10月〜2030年9月が50%、2030年10月〜2031年9月が30%（民間の解説。国税庁の資料で【要確認】）。取り分の割合を決めるときに考える。

## 8 申請の確認（権利と安全だけ）

**基本：出来の良し悪しでは落とさない。通らないときは「ここを直せば出せます」と返し、直して出し直せる。**

### 8.1 申請のときに答えてもらう項目

1. これは**あなたが作った作品**ですか？（自作アニメのキャラ、自分で描いた絵、マナで描いた絵）
2. **他の人のキャラクター・ロゴ・ブランド・実在の人物（顔・似顔絵）・人が撮った写真**が入っていますか？ 入っている場合は、使ってよいという**許可の証明**を付けてください。
3. 自分や友だちの**顔写真・学校の名前や校章・住所・電話番号**が写っていませんか？
4. マナで描いた絵も、上の決まりは同じです。

### 8.2 確認の三段階

| 段階 | 誰が | 見ること |
|---|---|---|
| ① 自動チェック | システム（社内の画像分類・似た絵の検索） | 有名なキャラクターや商標に似ていないか／性的・暴力的・差別的な内容／顔写真・制服の校章・文字で書かれた個人情報 |
| ② 人の確認 | 運営 | 自動チェックで引っかかったもの＋全件をざっと。**権利と安全だけ**を見る。目安2営業日以内 |
| ③ 公開後 | 誰でも／権利者 | 各商品ページの「お知らせする」ボタン、権利者からの申し立てフォーム。問題があれば一時的に止めて作者に知らせ、作者は意見を出せる |

- 画面には「AI」という言葉を出さない（「自動のチェック」「確認」と書く）。
- 確認を通っても、権利の責任がなくなるわけではない（LINE の規約と同じ考え方）。ただし**売り手は OBOLO なので、権利侵害の責任を OBOLO が負う可能性が高い** → 規約と責任の分け方を弁護士に確認。

### 8.3 通らなかったときの文言の例

> もう少しで出せます！
> このグッズは、次のところを直すとおぼろ商店に並べられます。
> - 右下のロゴが、ほかの会社のマークに似ています。消すか、自分で考えたマークに変えてください。
> 直したら、もう一度「出したい」を押してください。アトリエに飾るのは、このままで大丈夫です。

- **アトリエに飾ること**と**おぼろ商店で売ること**は分ける。売れなくても、（安全の問題がない限り）アトリエには飾れる。

## 10 開店前に確認すること

### 弁護士
1. 返品特約（お客さま都合は不可、不良は7日以内）で足りるか。契約不適合責任など、外せない責任は何か。
2. 特商法13条の通知・12条の6の最終確認画面の文言が足りているか。「遅滞なく」の考え方。
3. 注文確定後の取り消しをどこまで受けるか。
4. 売り手が OBOLO のときの**権利侵害の責任**と、作者との規約の分け方。
5. 未成年の作者の**保護者の同意**の取り方（何を記録するか）。15歳未満の扱い。
6. 工場との**委託契約**に入れる項目（使ってよい目的、再委託、安全管理、消す期限、漏えい時の報告）。**令和8年改正個人情報保護法**（2026年7月10日成立、7月17日公布、施行は公布から2年以内）で、委託先の目的外利用を禁じる規定が入ったか【要確認】。
7. 住所の間違いで戻ってきた荷物の送料の扱い。

### 税理士
1. 作者の取り分が**源泉徴収**の対象になるか（契約の形で変わるか）。
2. **支払調書**とマイナンバーの集め方。
3. 未成年の作者の所得は誰のものか（本人か保護者か）。振込先の名義。
4. インボイスの経過措置（70%→50%→30%）を、取り分の割合と価格にどう入れるか。
5. 返金時に戻らない決済手数料の会計の扱い。

### 工場（イメージ・マジック／Printio／提携候補）
1. API の仕様書・認証・テスト環境・呼び出し回数の上限。Webhook があるか（製造ステータス・追跡番号）。
2. 各品目が**1個から**作れるか（特にイメージ・マジックの缶バッジ「10個から」の表記、ステッカー）。
3. **送り主名を OBOLO（おぼろ商店）にできるか、納品書なし・同梱物なしにできるか**。
4. 品目ごとの**製作の営業日数**と、繁忙期・休みの日の予定。
5. **卸値**、API の利用料・初期費用・月額、送料（全国一律か）、請求の締め。
6. **不良品・誤配送・運送事故のときの作り直しと費用の負担**、不良とみなす基準。
7. 個人情報の安全管理と、委託契約を結べるか。
8. **15〜20歳向けのアプリと組むときの審査条件**、扱えない絵柄の基準。
9. 入稿データの決まり（解像度、色、アクスタの切り取り線・白板）。
10. 連絡先：イメージ・マジックの partners@imagemagic.co.jp は2016年の資料の記載なので、今も使えるか【要確認】。
