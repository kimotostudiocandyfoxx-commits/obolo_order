# マナの値段（2026-11-25 利用者決定・R17）

画像・曲・動画・ゲーム・本・声・おしゃべり、どれも同じ一つの式でマナの数を決める。
数字はすべてサーバーの「値段の仕組み」から出る。画面に新しく出すものはなく、確認のカードの「使うマナ ◯」が正しい数になるだけ。

## 1. 式

```
1円 ＝ 1マナ
使うマナ ＝ 切り上げ（（原価 ＋ 決済手数料ぶん）× 1.08）
         ＝ 切り上げ（ 原価 ÷（1 − 手数料率）× 1.08 ）
```

- **原価**：その作品を作るのに、外のサービス（Runware・Gemini・Claude・Fish）と自社の GPU / CPU に払うお金（円）。
- **決済手数料ぶん**：マナは、月88円・マナジェム（88円・888円・8,888円）で買われる。その円から Stripe が手数料（3.6%）を取るので、1マナで運営に残るのは 0.964円。原価を取り戻すには、原価 ÷ 0.964 が要る。
- **8%**：運営の取り分。原価＋手数料の上に乗せる。
- 共通の関数は `manaFor(costJpy)`（`packages/shared/src/manaPrice.ts`）。テストは `manaPrice.test.ts`。

### 計算の例

原価が **10円** の作品：

1. 手数料ぶんを足す：10 ÷ 0.964 ＝ 10.373…円（手数料ぶん 0.373…円）
2. 8% を乗せる：10.373… × 1.08 ＝ 11.203…
3. 切り上げ：**12マナ**

確かめ：12マナ × 0.964 ＝ 11.57円が運営に残る ≧ 10円 × 1.08 ＝ 10.8円。

```

```

### 0.1 マナの引き方（台帳は整数のまま）

- OK の時：**整数の分はすぐ台帳に1行**（0.3 のように1未満なら 0 の行。OK の印になり、二重に引かない）。**小数の分（0.1 の数）は、人ごとにためる**（`usage_accruals.pending_tenths`、移行 `0052_mana_tenths.sql`）。
- たまった 0.1 が 10 になったら、1マナを台帳に1行で引く（理由 `usage`、`ref_type` は作品の種類）。お財布の履歴では、月ごとに「つかったマナ（絵）」「（曲）」「（動画）」「（ゲーム）」「（お話）」にまとめて見せる（無料の機能は今までどおり「（おしゃべり・声など）」）。
- 返す時（作れなかった・動かなかった）：整数の分は返金の行、小数の分はためた数から引く（0 より下になってもよい＝次の分から使う）。返すのは一度だけ。
- だから「見せた値段」＝「引いた（引く）値段」。残高の表示は整数のまま（ためている小数は、気づかないくらいの差）。
- 1未満の作品でも、マナが0のときは作れない（NO_MANA）。無料の機能は、会員でない人（はじめの旅のあと）だけマナ0で止まる（12.）。
- 取り分の確かめでは、作品の種類の `usage` 行もその作品のマナとして数える。

- **はじめのマナジェム（STARTER_GEM_MANA＝40）**：旅で作るもの（コロリンのデザイン・アート・曲・MV を各1回＋作り直し1回。姿と着せ替えは旅の間は無料）は、

  - 絵を klein 4B にした時：(1.6＋0.4＋2.6＋6.4)×2 ＝ **約22マナ**。
  - ほかに、おしゃべり・声・スペルなどの小さな原価が旅で 10〜25マナほど（話す量しだい）。
  - おすすめ：安い絵のモデルにするなら **50**（今の 40 でもほぼ足りるが、よく話す人は7日目ごろに足りなくなる）。R16 のモデルのままなら 130。数は運営が決める（P-WALLET-2）。サーバーの数は変えていない。

## 3. 無料の機能の「小さな原価」

バティとのおしゃべり・調べもの・声（TTS）・スペルづくり・歌詞・コンパス・マナなしの曲の手直し・動画の作り直し（CPU）・本の章・リンクの読み取り・記憶のまとめ・2日目の姿づくり なども、1回ごとに原価を記録する。

**グッズ（2026-11-25 物語の部屋の答え・月のアトリエ）**：自分のアートを種類（トート／Tシャツ／ステッカー／アクスタ／マグカップ／缶バッジ）の見本にのせるだけで、絵は描かない（のせる絵はアプリがコードで合成する。有料の絵のモデルは使わない）。だから**マナの値段はなし（確認のカードもなし、0マナ）**。かかるのは小さな原価だけ：名前と主分類の言葉の確認（作った時と飛ばした時のタグ付けの `moderateText`、Flash-Lite）と、自分で名前を言った時の確認。どちらも、その要求の小さな原価としてためる（`featureOfPath`：`/moon/goods` は `other`）。保存は行1つ（アートのファイルは共有で、コピーしない）なので、保存の値段は足さない。かわりに1日 `GOODS_PER_DAY`（30）まで（本の章と同じ考え方）。ゲームのケースの絵をバティが描く時は、アートと同じ `jacketArt`（スペル・OK・引き落としもアートと同じ）。

- 原価（円）を、人ごとにためる（`usage_accruals.pending_jpy`）。
- たまった額が同じ式で **1マナ以上** になったら、その整数のマナを台帳に1行で書く（理由 `usage`、`ref_type` は機能の名前、冪等キー `usage:{利用者}:{通し番号}`）。端数は次にためる。
  - 例：おしゃべり1回 ≒ 0.08円（Haiku 5.5、入力3,000・出力400トークン）。1マナ分は 0.893円なので、だいたい12回で1マナ。
- **R18 から：マナが0のとき、会員でない人（はじめの旅のあと）は止まる**（下の 12.）。会員と、はじめの旅の間は止めない。引けなかった分は運営が吸収し、ログ（「unrecovered small cost」）と `usage_accruals.absorbed_*` に残す。持ち越さない。
- ダチとのおしゃべりの原価は引かない（宣伝費として吸収。12.）。
- 残高は決してマイナスにならない（台帳の `applyDelta` の決まりのまま）。
- お財布の履歴では、月ごとに1行「つかったマナ（おしゃべり・声など）」にまとめて見せる（1回ずつは出さない）。

## 4. 為替（ドル→円）を毎月決める

- 月ごとのレートは `fx_rates` 表（月 YYYY-MM・日本時間）。決め方は次のどれか：
  1. **GitHub の Actions →「Mana FX and margins」→ Run workflow**：`usd_jpy` に数字（例 160）、`month` は空なら来月。管理の鍵は Google Cloud の中だけで使われる。
  2. 管理 API：`PUT /admin/mana/fx`（`x-admin-token`）本文 `{"usdJpy":160,"month":"2026-12"}`（month を省くと来月）。今のレートと値段は `GET /admin/mana/fx`。
  3. GitHub の変数 `FX_RATES`（例 `2026-12=158;2027-01=160`）を入れて Deploy API。表に同じ月があれば表が勝つ。
- その月のレートがなければ、**前の月までで一番新しいレート**を使い、警告をログに出す（前の月が無ければ入っている一番新しい月、何も無いときは `FX_USD_JPY`、既定 160）。
- **控えめに**：見直しの時の相場より少し円安の数字を入れる（円が安いほど原価は高く見える＝取りこぼさない）。
- 毎月の手順（運営）：月末（25日ごろ）に翌月のレートを 1. で入れる → 実行の結果に新しい値段が出る。

## 5. 実際の原価の記録と、毎日の確かめ

### 記録（`gen_costs` 表、移行 `0051_mana_costs.sql`）

外のサービスや自社の機械を1回使うごとに1行：利用者・種類（作品の MakeKind か、無料の機能の名前）・有料か・作品の ID（`job`）・サービス・モデル・USD・秒・円・その時のレート・正確か。

| 原価 | 取り方 | 正確さ |
|---|---|---|
| Runware（Seedream・FLUX.2 klein・Qwen・Animagine など） | すべての呼び出しに `includeCost: true`、返ってきた `cost`（USD） | **正確** |
| Gemini（文章・画像・TTS・コンパス・聞き取り） | `usageMetadata` のトークン数 × モデルごとの値段表（思考トークンは出力として） | **正確**（値段表が合っていれば） |
| Claude（バティの会話・調べもの） | `usage` のトークン数 × 値段表、Web 検索は1回 $0.01 | **正確** |
| Fish（声・歌） | 文字のバイト数 × $15/100万バイト | ほぼ正確 |
| 自社 GPU（曲・GPU の絵） | 呼び出しの秒数 × `GPU_SECOND_JPY`（既定 0.05円/秒） | **見積もり**（起動待ちも入る） |
| Cloud Run の CPU（MV の描画・奥行き） | 作業の秒数 × `CPU_SECOND_JPY`（既定 0.01円/秒） | **見積もり** |
| Novita（予備の絵） | 1枚 $0.02 の定価 | 見積もり |
| Stripe の手数料 | `STRIPE_FEE_RATE`（3.6%）＋`STRIPE_FEE_FIXED_JPY`÷`STRIPE_FEE_BASE_JPY` | 設定どおり |

だれのための原価かは、リクエストと裏の仕事ごとの「原価の札」（`apps/api/src/wallet/cost-scope.ts`）で決まる。マナを引いた時（`LedgerService.charge`）にその札が「この作品・有料」になり、そのあと積まれる裏の仕事（曲・MV・ゲーム）にも引き継がれる。

### 値段を記録に合わせる

毎日1回（1台だけ）、作品ごとに直近30日の「1作品あたりの原価」が `COST_REFINE_MIN_SAMPLES`（既定20）件以上あれば、その **p90** を `make_cost_estimates` に書き、値段はそこから `manaFor` で出す。少ない間は上の見積もり表のまま。今すぐ：`POST /admin/mana/refine`。

### 取り分の確かめ（毎日）

- 作品の種類ごとに、直近1日と7日で「受け取ったマナ（返したマナを引く）× 0.964」と「記録した原価」を比べる。取り分 ＝ 受け取ったマナ × 0.964 ÷ 原価 − 1。
- **8% を下回る種類**があれば、エラーのログに「種類・今の値段・記録から出した値段（p90 を `manaFor`）」を出す。
- 見る場所：
  - `GET /admin/mana/margins?days=1`（または 7）— 管理の鍵。表・提案・日本語の行（`lines`）。
  - Actions「Mana FX and margins」（毎日 10:17 JST にも動く）。作品で 8% 未満があると失敗になり、GitHub からお知らせが届く。行は実行のまとめに出る。
  - 小さな原価（`usage`）の行も出すが、1マナにならない端数や 0マナで吸収した分があるので、日によって低く見える。失敗にはしない。

## 13. ブルーナの袋とふくろの魔法（R18・2026-11-25 利用者決定）

**言葉（依頼主 2026-11-25）**：アプリの世界では、保存の広さを「GB」「容量」と言わない。単位は **袋（ふくろ）**、**1袋 ＝ 1GB**。魔法の名前は **「ふくろの魔法」**（前の「保存の魔法」は言わない。利用者が言ったら同じ意味として聞く）。コード・設定（`STORAGE_*`）・表の列（`…_gb`）・API の道は GB のまま（1GB が画面の1袋）。台帳の理由も `storage` のまま。

保存は Cloudflare R2 に移す（配信＝egress は無料、保存は **$0.015 / GB・月**、R2 の料金ページで確認）。値段は R2 から決める（`STORAGE_GB_MONTH_USD`）。

### ブルーナの袋

| だれ | ふくまれる袋 |
|---|---|
| 会員（オボロオーダー、いま有効） | **5袋**（5GB、`STORAGE_MEMBER_GB`） |
| 会員でない人 | **1袋**（1GB、`STORAGE_FREE_GB`） |
| ふくろの魔法を唱えている人 | 上に ＋10袋／＋30袋／＋100袋 |

数えるのは、その人のものとして保存しているもの全部：とりこんだ写真・動画・音・ファイル、作った作品（曲・動画・絵・姿・コロリン・声）と、その版・分けた音（stems）・君の声の版・ポスター・場面の絵（`media_objects` の大きさの合計、消したものは数えない）。本とゲームはファイルを持たないので、文字（章・スペル・ゲームのコード）の大きさを足す。

ブルーナの見出しの下に、小さな袋の列（`components/bluena/StorageBar.tsx`・`BagRow.tsx`、数え方は `bagBar`）。部屋の袋1つに袋の絵1つ（会員なら5つ）、使ったぶんだけ左から満ちる。数字は出さない。袋が10より多い時は、10袋ぶんの大きな袋（帯のある袋）にまとめ、残りを1つずつ（15袋 → 大1＋小5、35袋 → 大3＋小5、105袋 → 大10＋小5。電話の幅でもはみ出さない、多くて16こ）。読み上げは「ふくろ 5つのうち、2つぶんくらい」（からの時「まだからっぽ」、少しの時「すこしだけ」、いっぱいの時「ぜんぶいっぱい」）。

### ふくろの魔法の値段（1か月）

```
1か月の原価（USD）＝ 袋の数（GB）× 0.015（保存代だけ。依頼主 2026-11-25）
使うマナ ＝ manaFor10（ 原価 × その月の為替 ）　…（1.の式、0.1 マナきざみ）
```

- R2 の操作（Class A $4.50／100万回、Class B $0.36／100万回）は値段に入れない（依頼主 2026-11-25：保存代だけ。操作はほぼ無料枠に収まる見込み。毎日の利益チェックで実額を見て、必要なら `STORAGE_CLASS_A_PER_GB` / `STORAGE_CLASS_B_PER_GB` で足す）。

| ふやす袋 | 1か月の原価 | 円（160円/ドル） | **マナ／月** |
|---|---|---|---|
| ＋10袋 | $0.15 | 24.0円 | **26.9** |
| ＋30袋 | $0.45 | 72.0円 | **80.7** |
| ＋100袋 | $1.50 | 240.0円 | **268.9** |

### 唱え方（言葉だけ、ボタンなし）

1. 「ふくろの魔法」「袋をふやして」「袋を増やして」「ふくろをふやす」（前の「保存の魔法」「ブルーナを広げて」「容量を増やして」も同じ）→ バティが一文で：「ブルーナの袋をふやす、ふくろの魔法。ひと月10袋が26.9マナ、30袋が80.7マナ、100袋が268.9マナだよ。どれにする？」
2. 袋の数を言う（「10袋」「じゅう袋」「30袋」「百袋」「いちばん大きいの」、前の「30GB」「百ギガ」も）→「30袋を、ひと月80.7マナだね。唱える？」（聞きとれない時「いくつふやす？　10袋、30袋、100袋から選んでね。」）
3. OK → 確認の印（MakeConfirm と同じ形：新しい ID と見せた値段）で `POST /storage/expand`。値段が今と違えば引かない（PRICE_CHANGED）、同じ印は二度引かない。マナが足りなければ引かない（NO_MANA）。
4. その場で **1か月ぶん**（日割りなし）を引き、すぐ袋がふえる（「ブルーナの袋が30ふえたよ！」）。そのあとは **毎月はじめ**（日本時間の月）に、毎日の仕事（6時間ごと・1台だけ）と、ブルーナを開いた時に引く。
- 台帳：理由 `storage`、冪等キー `storage:{利用者}:buy:{確認ID}`（買う時）・`storage:{利用者}:renew:{月}:{GB}`（毎月）。整数の分は1行、小数の分は 0.1 マナと同じくためる。

### マナが足りない時・やめる時

- 更新でマナが足りない：ファイルはそのまま。**7日待つ**（`STORAGE_GRACE_DAYS`、その間は袋の数はそのまま）。バティが一度だけ「マナが足りなくて、ふくろの魔法が続けられなかったよ。{n}日のうちにマナがたまれば、そのまま続くよ。」。待つ間も毎日引きなおす（マナが入れば続く）。7日すぎたら魔法がとける（「ふくろの魔法がとけて、ブルーナの袋がもとの数にもどったよ。作品は消えていないから、安心してね。」を一度）。
- 「ふくろの魔法をやめて」（前の「保存の魔法をやめて」も）：今月の終わりまで袋はそのまま、来月は引かずにとける（「ふくろの魔法は、今月でおしまいにするね。来月から、もとの袋の数にもどるよ。」）。
- とけた時にもとの袋より多く入っていても、**何も消さない**。新しく保存すること・作ることだけが止まる（下より少なくなるまで）。

### 知らせ

- 80%：バティが一度だけ「ブルーナの袋がいっぱいになってきたよ。いらないものを消すか、ふくろの魔法で袋をふやせるよ。」（75% より下がったら、また言える）。
- 100%：作る（マナを使う作品は引く前に）・とりこむ・本の章・ゲームが止まり、「ブルーナの袋がいっぱいだよ。いらないものを消すか、ふくろの魔法で袋をふやしてね。」（`STORAGE_QUOTA`）。消すこと（DELETE）は止めない。
- どの台詞も性格ごとの言い方がある（`packages/shared/src/storageVariants.ts`、物語チャットに確かめてもらう仮の台詞）。

### 消す

ブルーナで作品を開くと、下に小さな〔消す〕（確かめてから）。作品・その中の別の版（月の作品の試し）・星に飛ばしたもの・MV の元・ファイル（曲の mp3・元の曲・分けた音・君の声の版、動画の MP4・ポスター・場面の絵、本の表紙…）を消して、袋に空きがもどる（`DELETE /storage/works/:kind/:id`）。ほかの自分の作品がまだ使っているファイルは残す。自動で消すことは決してない。
