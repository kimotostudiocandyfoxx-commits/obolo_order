## 失敗の原因（ログから）

### 1. Runware が「残高の予約が足りない」と断る（いちばん大きい）

クラウドのログ（13:00〜）に出ているもの：

```
13:00:12  ERROR  Seedream 400 [{"code":"concurrentRequestLimitExceeded","message":"Insufficient available balance. 1.99 credits are currently reserved for requests in progress, and t…   at LookService.standee
13:00:13  ERROR  （同じ）                                                                 at LookService.standee
13:01:42  WARN   bati generation failed (1): Seedream 504 [{"code":"failedTaskTimeout","message":"Task processing timeout. Results were not received within the expected time window…
13:01:43  WARN   bati generation failed (2): Seedream 400 concurrentRequestLimitExceeded "… 1.194 credits are currently reserved …"
13:01:44  WARN   bati generation failed (1)/(2): Seedream 400 concurrentRequestLimitExceeded
13:02:08  WARN   bati face smile / sparkle / surprise / think / sad failed: Seedream 400 concurrentRequestLimitExceeded
```

- 名前は「同時の数の上限」だが、中身は「**使える残高が足りない。いま描いている分のために 1.99（1.194）クレジットを取り置いている**」。Runware は描き始める時に料金を取り置き、**取り置きの合計が残高をこえると、新しい注文を断る**。つまり、**Runware の残高が少ない**ことが元で、同時に投げる数が多いほど早く断られる。
- サーバーは「1台で12枚まで」に絞っているが、Cloud Run は最大20台（`deploy-api.yml` の `--max-instances=20`）なので、**アカウント全体では絞れていない**。
- 試しは、姿6件×4枚＋誕生8件＋会話3本を**同時に**流している（`Promise.all`）。

- いちごの顔が0枚になった理由も、ログに出ていない。

## 開発の人がすること（失敗について）

1. **Runware の残高を足す**（自動チャージも）。試しの前に管理画面で残高を確かめる。本番の初日も同じことが起きるので、「いちばん混む時に同時に描く数 × 1枚の値段」より多い残高を常に持つ。
2. **アカウント全体で、同時に描く数を絞る**：いまの「1台で12枚」では20台で240枚まで投げられる。仕事の列（`bati.paint` と同じ列）か、共通の数え札（Redis などのセマフォ）で、全体で例えば8〜10枚まで。または、絵を描く仕事だけを1台の係にまとめる。
3. **やり直しの仕方**（`529fcf1a` で一部入った）：
   - `concurrentRequestLimitExceeded` は待ってやり直す（入った。8・16・24秒で3回）。**この直しはまだ試していない。**
   - `504 failedTaskTimeout` もやり直しに入れる（いまは入っていない）。
   - バティの2回目はすぐに投げない（1回目の `504` の1秒後に `400` で落ちている）。
   - 待つあいだ、描く枠（`running`）を持ったままなので、列がさらに長くなる。待つ時は枠を返す。
4. **立ち絵・ちびを `500` にしない**：失敗したら列に入れなおし、できるまでは選んだ姿の絵（背景つき）を出す。クライアントにはわかるエラーの名前（例 `PAINTER_BUSY`）を返す。
5. **バティの「代わりの体」に印をつける**（例 `batiFallback: true`）。台本の山場は「好きな食べ物がバティになる」なので、体のままは「失敗」。印のついたバティは、裏で描きなおし、できたら差しかえる（D03-S008 の会話まで、または次に開いた時）。
6. **テストを正直にする**（`scripts/smoke/gentests.mjs`）：
   - バティの絵がたまごの体と同じなら「fallback」と書く（サーバーが印を返すのがいちばん確か）。
   - 6つの顔は「6つ中いくつ」と表に書く。0〜5つは失敗。
   - 立ち絵・ちびの失敗も表に行を作る（いまはエラー欄にしか出ない）。
7. **クラウドのログの窓を、試しの始まりから**にする（例：試しの実行が始まった時刻の1分前）。`look generation failed` も見えるようにする。
8. **試しの流し方**：「本番の初日のように同時に流す回」と「1件ずつ流す回」を分ける。1件ずつの回で絵の出来を見て、同時の回で失敗と待ち時間を見る。いまは同時の回しかないので、出来を見たい所（おにぎり・顔・立ち絵）が毎回、失敗でつぶれる。
