# 月の工房とブルーナ ― 作る・しまう・見せるの設計（2026-11-21 利用者決定）

物語側の正本：`claude/hopeful-pascal-udqkh2` ブランチの `docs/story-rewrite/wip/decisions_round20.md`（M-R185〜M-R197）。
この文書は UI・設計の正本。物語の決定と食い違う所は、物語チャットと合わせてから直す。

> **呼び方（2026-11-21 利用者決定）：画面に出す名前は「月で作る」。** 「工房」は使わない。入口は〔つくる〕、画面の名前は「月で作る」、各惑星とブルーナのボタンは〔月で作る〕。
> この文書の「月の工房」は場所の説明として残す（物語チャットに、台詞の呼び方をそろえてもらう）。

## 0. 一言でいうと

> **作るのは月、しまうのはブルーナ、見せるのは星。**

これまでは「水星で作曲・火星で撮影・金星（天王星）でつくる」と、作る場所が惑星ごとに分かれていた。
MVを実際に作ってみると、1つの作品が曲・絵・動画・物にまたがるため、作る場所は一か所にまとめた方が自然だと分かった。

| 場所 | 役割 | 見られる人 |
|---|---|---|
| **月の工房** | バティと話して作る（曲・アート・写真の加工・動画・MV・グッズ・本・ゲーム） | 自分だけ |
| **ブルーナ** | 作品をしまう（種類ごとのフォルダ）〔作品〕と、ダチとのやり取り〔通信〕。工房への入口 | 自分だけ |
| **各惑星の自分の場所**（水星の島・火星のスタジオ・木星のアトリエなど） | 公開した作品を飾る・見てもらう・他の人の作品と出会う | みんな |

いちばん大事な決まり：**「自分だけの場所（月の工房・ブルーナ）」と「みんなが見る場所（惑星）」をはっきり分ける。**
惑星の中に非公開の保存場所を混ぜると「これは他の人に見えているの？」が分からなくなるため。

例外は2つ（物語の決定 M-R190・M-R193）：金星の放送ブース（10章）と、土星でその場で声を落とすコロリン・マイクリレー。どちらも「作る」と「見せる」がその場で同時に起きる。

## 1. 物語の筋

### 1.1 ブルーナ
- OBOLON から受け取る。「地球のブルーに、月のルナ。地球と月、宇宙を繋げるもの」（今の台本のまま）。
- ブルーナの中には **月へつながる門** がある（今の台本の「Bluenaの門」）。
- **〔つくる〕を押すと、ブルーナの門が開き、正方形のスクリーンに月の工房が映る。** そこで作る。
- **作品はブルーナの中にしまわれる**（自分だけの作品集）。
- **公開＝ブルーナから惑星へ投影する。**「Bluenaで投影する」をそのまま公開の動きにする。
- ブルーナには二つの道がある（13章）：地球と月を結ぶ道（いつでも開いている）と、遠い星への門（一日88分）。

### 1.2 月の工房
- 月の神殿の中にある、バティの工房。バティが生まれた場所であり、バティの家。
- 今の台本の「また、月に来てね。いつでも、話せるから。」（バティ）、「この先の星でも、作る時は、{bati}と、話して、作る。」（OBOLON）とつながる。

### 1.3 バティの居場所
- **バティの家は月。ブルーナの門が開いている間だけ、門を通って隣に来てくれる。**
- 旅の間：ブルーナの光から現れて隣にいて、各惑星の案内役の話に反応する。
- 〔つくる〕：バティが「工房に行こう」と言い、月の工房へ。
- 一日88分が終わると星への門が閉まり、バティは月へ帰る（今の MONBAN の台詞のまま）。地球と月の道は開いたままなので、月の工房ではいつでも会える。
- マナ切れ：門を通って出てくる力が弱まる、と見せる。
- ✏️ 案（運営の確認待ち）：ORDER になる前のバティはブルーナの光でできた仮の姿で、隣にいられる時間が短い。ORDER になると本当の姿になり、隣にいられる時間・一緒に作れる量が増える（会員になる分かりやすい理由になる）。

## 3. 画面

### 3.1 入口（ホーム・各惑星の共通）
- 画面の決まった場所に **〔つくる〕**（月のしるし）と **〔ブルーナ〕**（ブルーナの絵）を置く。どの星にいても同じ場所。
- 〔通信〕に新しいやり取りが届いたら、ブルーナのアイコンに小さな光の印（数字は出さない）。

### 3.2 月の工房
- 開く時：ブルーナの門が開く演出 → 正方形のスクリーンが広がって工房の中へ。
- バティとのチャットで作る。最初に「何を作る？」を記号のボタンで選ぶ（音符・再生・正方形の額・放送の電波・宝石・音の波・開いた本・ゲームの札・おまかせ）。
- できたら、バティ：「ブルーナにしまったよ」→ 作品は自動で種類のフォルダへ。
- その場で **〔公開する〕**（行き先の惑星のアイコン付き）を押すか、あとでブルーナから公開する。
- 各惑星の自分の場所から〔月で作る〕で来た時は、その星の種類を選んだ状態で開く。

### 3.3 ブルーナ
- 正方形のスクリーンの形。画面は **〔作品〕と〔通信〕の二つ**（11章）。切りかえは記号（作品＝正方形の作品集のしるし、通信＝吹き出し）。字は出さない。
- 〔作品〕：上に惑星のアイコンを横一列に並べる。
  - **アイコンの下に文字は付けない。** 惑星のアイコンの右下に小さな記号（2.1）を重ねて、何のフォルダか分かるようにする。
  - 読み上げ（アクセシビリティ）用の名前は付ける（画面には出さない）。
  - 長押しで名前が小さく出る。初めて開いた時だけ、記号の意味を一度だけ案内する。
- アイコンを押すと、その種類の作品が並ぶ。各フォルダは「自分の作品」と「しまった作品」の2つ（8章）。
- **フォルダの見た目は、その星の世界観にする**（例：水星は島の土の中に埋まったレコード、火星は裏スタジオの棚、木星は木の根っこ、冥王星は氷の書庫）。これまで惑星ごとにあった非公開の保存場所の見た目を、ブルーナの中のフォルダとして残す。
- 公開した作品には「公開中」の小さな印と、公開先の惑星のしるし。
- 各作品：〔公開する〕〔工房で続きを作る〕〔消す〕。

### 3.4 各惑星
- **作る機能は持たない**（「作曲」「撮影」「つくる」のタブはやめる）。
- 自分の場所（島・スタジオ・アトリエ・店・図書館など）は「公開した自分の作品を飾る所」。他の人の作品と出会う場所（海・星図・空・広場など）はそのまま。
- 自分の場所には〔月で作る〕を1つだけ置く（その星の種類で工房が開く）。
- 惑星ごとの楽しさ（船の出航、UFO の発進、蝶が飛ぶ、ころりんが落ちてくる、灯りがともる）は、**公開した瞬間の演出** と、他の人の作品と出会う場面で出す。

### 3.5 公開の流れ（どの作品も同じ一方通行）
1. 月の工房で作る
2. ブルーナにしまわれる（種類のフォルダへ自動）
3. 〔公開する〕
4. ブルーナから惑星へ投影する演出 → 惑星ごとの姿になって出ていく（船・UFO・蝶・ころりん・灯り…）

## 7. 冥王星＝物語の星（2026-11-21 利用者決定・M-R188）

- 本・小説・絵本は **冥王星** に飾る。小説はアニメ（火星）・ゲーム（海王星）・グッズ（天王星）の元になるので、物語には専用の星を持たせる（「一つの星に一つの種類」）。
- 世界観：太陽からいちばん遠い、暗くて冷たい星。「惑星から外された、忘れられた星」に物語がしまわれる。
- ブルーナの冥王星フォルダ：見た目は **氷の書庫**。物語が氷の結晶の中に眠っている。記号は **開いた本**。
- 公開した時の姿：暗い冥王星の空に、物語が一つずつ **灯り** としてともる。読まれるほど明るくなる（明るさは数字にしない）。
- 読む画面：ページをめくる本の形（小説は文字、絵本は見開きの絵と文）。
- 他の作品とのつながり：本のページから〔この物語でアニメを作る〕〔絵本にする〕で月の工房へ（その本を元にした状態で開く）。できたアニメは火星、絵本の印刷は天王星の obolo商店へ。元の本へのつながりを持たせる。
- 地図：一周目は扉だけ見える星、二周目のはじめに開く。住人はたこ焼きブラザー（バイカ）を移す初期案（✏️ 利用者の確認待ち、M-R188）。
- 物語の伏線：9日目、KIMORIN の「今日は冥王星！」がバティのマナ切れで行けずに終わる。✏️ 案（物語チャット・運営の確認待ち）：冥王星を **ORDER になった次の日に最初に行ける星** にして、伏線を回収する。冥王星が開くまでも、本は月の工房で作ってブルーナにしまっておける。

## 8. 他の人の作品をブルーナに保存する（2026-11-21 利用者決定・M-R187）

- 惑星で他の人の作品に出会って気に入ったら、**〔ブルーナにしまう〕** で自分のブルーナに保存できる（まずは水星の曲。同じ仕組みを他の星にも広げる）。
- ブルーナの各フォルダは **「自分の作品」と「しまった作品」** の2つに分かれる。切り替えは文字ではなく記号（しまった作品＝小さなしおり）で表す。
- しまった作品は **いつでもブルーナから聴ける・見られる**。
- しまった作品は「写し」ではなく「つながり」として持つ。作った人が消した・非公開にした・通報で止められた作品は、聴けなくなる（「今は聴けません」と表示）。
- 誰が何人しまったかは、画面に出さない（人数・評価を出さない決まり 2026-11-02 のまま）。作った人へ「あなたの曲がブルーナにしまわれた」と知らせるかは ✏️ 運営の確認待ち。

## 9. 金星＝ラジオの星（2026-11-21 利用者決定・M-R190）

金星は「DJ・VJ の星」（2026-10-12）から、**ラジオ・ポッドキャストの星** に変える。DJ は番組の中の機能の一つ。だから番組のために DJ を練習する、という流れになる。

### 9.1 他のポッドキャストとの違い
- このアプリのユーザーは自分の曲を持っている。自分の曲や、ブルーナにしまった他の人の曲を BGM・ジングルにして、DJ のようにつなぎながら話す番組が作れる。

### 9.2 ブルーナ＝DJ の USB
- 番組作り（金星の放送ブース。10章を参照）では、**ブルーナを DJ 機材に差し込む** と、ブルーナの中の曲（自分の曲＋しまった曲）がデッキに読み込める。DJ が USB を差すのと同じ立ち位置。
- 番組で流せる曲：**このプラットフォームで生まれた曲**（自分の曲、ブルーナにしまった他の人の曲）。
  - 曲を水星で公開する時に「このアプリの中のラジオ・DJ で使われて OK」を最初からオンにし、作った人がオフにもできる（利用規約にも書く）。オフの曲はデッキに読み込めない。
  - 流れている間は、曲名と作った人を画面に出す。聴いている人は、そこから作った人の水星の島へ行ける。
  - ✏️ 将来の案：流れた回数に応じて作った人に還元する（「作った人に92%」の考え方）。最初は名前の表示と通知だけ。
- 既存の有名な曲（端末の中の音楽ファイルなど）は、**DJ の練習（自分だけ）にだけ** 使える。番組の収録・配信には使えない（運営が管理団体・レコード会社と契約するまで）。

### 9.3 番組の形
- **声だけ**（映像の配信はしない）。
- ただし **サムネ（番組の絵）と、簡単なループ画像（短いループ動画・動く絵）** を回せるようにする。ループ画像は番組の情報として送り、聴く人のアプリで流すので、配信の通信量はほぼ増えない。サムネ・ループ画像は月の工房で作るか、ブルーナの絵・動画から選ぶ。
- 番組中にかけた曲は、画面に曲名と作った人が出る（9.2）。
- リクエスト：聴いている人が、水星の曲からリクエストを送れる（生配信の時）。

### 9.4 進め方
1. **第1段階：収録の番組（ポッドキャスト）**。放送ブースで、ブルーナを差して DJ しながら話して収録 → ブルーナの金星フォルダ → 金星で公開。
2. **第2段階：声だけの生配信**（開発に入れる）。通報・配信の強制停止・ブロックなどの決まりを整えてから一般に開く。最初は ORDER だけが配信できる形。通信量課金のサービス（例：Cloudflare Realtime。毎月1,000GBまで無料、その後1GBあたり0.05ドル）を使う。配信が終わると録音が自動で残り、番組の回として金星で流せる。
- 今ある DJ の音声エンジン（Signalsmith Stretch など、`apps/web/lib/dj/`）は、放送ブースの DJ 機能としてそのまま使う。

## 10. 金星の放送ブース（2026-11-21 利用者決定）

## 15. マナはふつうのポイント（2026-11-21 利用者決定）

ブロックチェーンや独自のコインは使わない。マナは、運営が値段を決めるふつうのポイントとして扱う。

1. **台帳は書き足すだけ**：`mana_ledger` に増減を1行ずつ記録し、行の中身は書きかえも削除もしない。残高は台帳の合計で、`wallets.mana_balance` はその控え（同じ取引の中で一緒に更新する）。
   - 行の中身：利用者 ID、増減、その後の残高、理由（`monthly_grant`・`purchase`・`generation`・`refund`・`admin_adjust` など）、関連 ID、時刻、冪等キー。
2. **書きかえに気づく仕組み（ハッシュチェーン）**：利用者ごとに行へ通し番号（`seq` 1, 2, 3 …）を振り、`hash = SHA-256（行の中身＋前の行の hash）` でつなぐ。最初の行は 0 が64個の値につなぐ。
   - 毎日1回（Redis の日付キーで1台だけ）、全員の鎖を確かめる。行の書きかえ・削除・後からの差しこみ、残高の計算の食い違い、控えの残高のずれを見つけたら、エラーとして記録する。自動では直さない。
   - 運営は管理用の鍵で `POST /admin/mana/check` を叩けば、いつでも確かめられる。
   - 外へは今は公開しない。
3. **マナの性質**：本人だけが使える。人への譲渡なし、換金なし。値段は運営が決める（月88円で88マナ）。資金決済法の自家型前払式支払手段の範囲に収める想定（法務の確認は別にする）。台帳にも、マナを円や他の人へ動かす処理は作らない（`packages/ledger` の決まりのまま）。
4. **フェスで使えるのは公式の物だけ**。第三者の店への広げ方は今は考えない。
5. **個人情報と分ける**：台帳の利用者 ID はランダムな番号（UUID）で、メール・名前などは `users` の方にある。退会・削除の求めには、`users` の個人情報を消し、台帳は番号のまま残す（P-MANA-1：退会の手順はまだ無い）。
6. **決済の二重付与を防ぐ**：Stripe などの知らせ（webhook）は冪等キーで受け、同じ知らせが二度来てもマナは一度しか増えない（今の仕組みのまま）。
7. **値段**（2026-11-25）：どのマナも「原価＋決済手数料ぶん」に 8% を乗せた切り上げ。無料の機能の小さな原価はためて、1マナになったら理由 `usage` の行で引く（0マナなら運営が吸収し、止めない）。詳しくは [マナの値段.md](マナの値段.md)。
